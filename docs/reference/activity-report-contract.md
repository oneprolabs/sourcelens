# 工作活动汇总契约

工作汇总继续由模型完成业务内容：解释请求范围、读取绑定技能与工作区账号映射、按人
整理工作、生成交付物，并提供简短结论。来源验证和证据账本用于支持与复核该过程，
不能直接替代业务报告，也不能因取证工具已返回而提前结束模型循环。
普通故障报告、代码总结及其他运行模式不进入活动证据链路。

## 来源与覆盖

Jira 使用 Server 的 startAt 或 Cloud 的 nextPageToken 分页；查询覆盖窗口内的
创建、更新、解决日期，再用精确时区时间过滤。默认最多 500 条、允许最多 1000 条，
每页最多 100 条，每个项目最多 10 页。重复页面或游标、预算耗尽及后续页失败均标记
possibly_truncated，保留前页记录。

GitLab 的全部项目模式枚举 token 可见项目，不额外限制 membership；每页 100 个，
最多 200 个项目。每项资源每页最多 50 条、最多 10 页；提交上限 1000 条，MR/issue
上限 500 条，默认结果上限 500 条。创建、更新、合并、关闭日期按精确窗口核验。

GitHub 每项资源最多 10 页、500 条。提交采用提交者日期，PR 按更新时间排序并核验
创建、更新、合并、关闭日期；issue 分别查询 updated、created、closed 后按编号去重，
避免历史关闭记录因后续更新落在窗口外而漏掉。搜索 incomplete_results 仍是覆盖限制。

这些是有界快照查询，不保证全部历史操作覆盖。列表页预算耗尽、响应错误、单工具结果
超过 900 KB 后的尾部裁剪，以及缺少任一预期来源，都必须进入报告覆盖限制。它们不能
被解释为无工作、无错误或已获得完整证据。

## 证据与交付

运行时在工作区私有 `.sourcelens/plugin-state/<Run hash>/activity-report` 保存来源投影与查询参数。
缓存按 provider、connection、plugin version、工具名和完整参数隔离；相同查询并发串行，
恢复后可复用。账本不保存 token、lease material 等认证内容；终态或 checkpoint 过期清理。
模型可以通过分页工具 `read_activity_evidence(offset, limit)` 复用规范化活动记录，
不重复抓取相同来源。该工具返回当前页、`total_records`、`next_page`、完整账本的
`observed_events` 汇总，以及按 provider/tool 分开的 `source_coverage`；读取完所需页后
才能按人下结论。它不生成答案、
上传文件或结束 agent graph。工具名和内部验证信息不应出现在用户最终正文中。

Host 按账本快照摘要持久化实际读取区间；重复页、跳页和旧文件内分页不会补齐未读区间。
来源或记录变化会使旧阅读进度失效，checkpoint 恢复则保留同一快照的进度。证据页按大小
自动缩小，必须跟随实际 `next_page`；超大的汇总元数据可显式省略，但原始账本保留。
汇总元数据超过页面预算的一半且页面超限时，先省略汇总元数据，再缩小记录页；较小的
事件汇总仍保留，以免前页遮蔽后页的完成事件。单条记录仍与较小汇总合计超限时，再省略
可选汇总后判断该记录是否可读。24,000 字符上限包含 `read_progress`，
仅在最终页面能够完整返回时持久化该页进度，不因试算或拒绝超大页面记为已读。
该工具以可信 `bounded_inline_result` 元数据声明自有分页，Host 保持页面 inline，避免
自动 offload 后模型只看到文件指针却被计为已经阅读。单条记录仍超限时拒绝该页，不能记为已读。

即使未绑定决策模型，结束检查和宿主附件校验也会拒绝未读完的报告，给每类问题一次
有上限的修正机会；仍未修正则以 partial 结束。来源完整性与阅读完整性分别记录，不能互相覆盖。
修正耗尽后撤下仍缺乏支持的最终断言与附件候选，返回明确的核验失败说明。
中文和英文的常见“零完成、低产出、长期停滞”断言会在聊天答案及文本附件中检查，HTML 按
段落和单元格检查，其他人的免责声明不能为该断言免责。只描述检索到的事件，并准确限定缺口。
这是一层针对已知表达的保守防线，不能代替语义核验，也不根据活动数量推导绩效。
“没有完成事件、记录或证据”是可报告的观测限制，不等于人员没有完成工作；
无依据的“零完成、低产出”等结论仍须拦截。
技能格式若要求无证据支持的“零完成、长期 review、低产出”等评价，保留版式，改为
已观察到的事件与明确的未知项。已保存的来源优先通过规范化账本读取；原始 JSON 分析
遇到 `FIELD_NOT_FOUND` 时切换至账本，避免反复猜测字段路径消耗交付窗口。

活动工作流激活时，首次和缓存来源调用都返回精简保存收据及账本读取入口，完整来源仍保留
在私有账本中。模型先收集所需来源，再读取规范化页面；收据本身不算已读记录，不能替代
人员汇总的证据。非活动工具与未激活工作流保持原有返回行为。

模型按绑定技能的 OUTPUT_FORMAT 整理内容；engineering-report 要求真实姓名展示、
完成的 / 正在做的 / 风险 / 评语以及 HTML 看板。跨系统合并必须依据工作区显式账号映射，
近似映射按技能要求披露，不以显示名相同证明身份相同。Jira 当前负责人、issue/MR 作者与
实际更新者仍需区分；当前 Done/closed 状态不证明窗口内完成，需来源日期支持。
规范化记录保留独立 `roles` 与 `event_actor`；仅显示名不是已验证账号。来源未提供关闭者、
合并者、解决者或更新者时，操作者保持未知，不能用作者或当前负责人补齐。事件汇总中的数量
表示与该角色关联的条目，不表示该人员亲自执行相应操作；Jira 本次不会额外逐条抓取 changelog。

最终文件写入 Run 私有目录下的 `deliverables/`，宿主在最终回答审核前自动校验并暂存，
再由最终回答发布候选清单。文件工具可使用 `/deliverables/report.html`，Shell/技能脚本须
使用 Run cwd 下的相对路径 `deliverables/report.html`。技能脚本保留原有 Skill cwd，通过
环境变量 `SOURCELENS_DELIVERABLE_DIR` 写入，或在结构化参数中使用
`{{SOURCELENS_DELIVERABLE_DIR}}/report.pdf` 占位符，由宿主解析到本 Run 交付目录。
模型不再调用 `save_deliverable`；
旧技能中的这一步由宿主交付契约取代。其他 scratch 文件不会自动公开。
验证驳回将交付目录移入私有隔离目录并清空候选批次与对应 append 收据，模型须重新生成
本次最终交付的全部文件。运行结束时保留模型答案和交付物，不再生成固定
活动 HTML/证据 JSON，也不以验证清单覆盖业务内容。
附件校验在上传前执行，拒绝结果附带需修正的具体句子。内容校验失败不消耗上传能力的
故障重试次数，修正文件后可重新校验同一路径；每次仍执行全部门禁。自动交付失败最多反馈
模型修正两轮，不会无限重试；运行终态再收集一次当前文件，覆盖预算收尾。任一文件失败
都不发布该批附件。相同字节复用候选 UUID，内容校验仍随最新证据重做；修改、删除或重传
失败会移除旧候选 UUID。目录仅接受普通文件，拒绝符号链接，最多64个文件，单文件上限沿用配置。
若文件正文已通过本次校验，而聊天说明另行加入无依据的人员评价，宿主只把聊天说明替换为
简短附件提示，保留已核验文件和来源缺口标记；文件自身不合格时仍拒绝发布并要求修正。
预算边界的文件写入窗口见 [交付物发布](../decisions/003-reviewed-deliverable-publication.md)。核验失败时，
终态详情保留导致收尾的预算或收敛限制，最终说明区分未读完记录与缺乏支持的人员结论。

`source_coverage_complete` 仅描述已收集来源快照是否报告缺口，不能证明日期、资源范围
等于用户请求。实际截断、缺失来源或请求失败继续使结果为 partial，并在业务报告中说明
影响；没有发现缺口时不硬编码“范围尚未核验”，也不强制 partial。范围与内容正确性仍由
模型按用户要求检查，并接受已绑定证据门禁的复核，未观察到的历史行为不能补造。
未取得来源时保留澄清问题或失败解释。

## 验证

`test_activity_pagination.py` 验证有界分页和部分来源结果保留。
`test_activity_reports.py` 验证持久复用、日期/身份语义、结果预算、分页证据读取、
同步/异步真实 graph 在取证后继续生成业务报告文件，以及终态保留答案与候选文件。
完整来源不会被固定提示标记为 partial；真实来源缺口仍为 partial。
`test_activity_report_contract.py` 验证提示词要求遵循绑定技能并生成最终交付物。
`test_activity_completion_guards.py` 覆盖阅读游标、恢复、快照失效、真实 offload 同步/异步路径、
负面结论及 HTML/XHTML/JSON 上传门禁、角色与操作者分离。

`test_deliverable.py` 验证真实 graph 自动暂存文件、预算及硬上限边界、校验恢复与候选失效。
