# 前端验证

## 本地检查

在 `frontend/` 下安装锁定依赖，使用以下命令检查单元行为和生产构建：

```shell
npm ci
npm run test:unit
npm run build
```

`npm run lint` 会自动修复文件。只需检查时使用项目 ESLint 对指定文件运行，不加
`--fix`。文档改动检查相对链接、被移动/删除文件的引用及 `git diff --check`。

## 浏览器验收

本项目默认用 **ego-browser** 检查真实用户流程。每次验收记录 task space、目标服务、
视口、语言、检查的操作及实际结果。不要将历史测试数量写成当前通过状态。

可按页面选择语言（en、zh-CN、es）、桌面/手机视口、成功/空态/错误状态。
必须验证矩阵轴确实生效：目标语言哨兵文本、手机元素、空态/错误提示以及当前路由。
检查控制台、请求失败、横向溢出、关键操作可达性和结果显示。

Mock 页面只证明呈现行为，不能证明真实鉴权或后端接口正确；重要保存、授权与
状态转换需要真实接口验证。截图用于辅助判断，不能替代操作结果。

## 现有测试资产

`frontend/e2e/ui-regression/` 保存路由清册、mock 夹具、场景、断言及视觉审计工具。
既有 Playwright 配置和测试文件保留；只有用户在当前任务明确要求 Playwright 时
才运行相关脚本。使用 ego-browser 不要求修改或删除这些项目资产。

静态 i18n 键集检查包含在单元测试中。新增场景应验证失败时确实能被检查发现，
例如缺少语言哨兵、空态标记或返回错误路由。确定性结果与截图不一致时需要复核。
